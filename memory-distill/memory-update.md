# Memory Update

定义什么内容值得沉淀，以及候选记忆与已有记忆之间如何处理。

记忆 ID、字段格式、文件写入和索引维护按照 `storage.md` 执行。

## 记忆准入

只从当前会话中提取满足以下条件的内容：

1. 来自明确事实、用户确认的决策或已经验证的经验
2. 在后续任务中存在再次使用的可能
3. 脱离当前会话后仍能独立理解
4. 能够说明适用范围或成立条件

任意条件不满足，不写入长期记忆。

可以沉淀的内容包括：

* 已经确认的决策或设计取舍
* 经过验证的问题解决方式
* 可以复用的方法或处理模式
* 对项目长期有效的环境、平台或业务约束
* 用户明确表达的长期工作偏好
* 有明确原因、结果和复用价值的失败经验

不得沉淀：

* 对话流水账和大段原始内容
* 普通知识问答
* 临时任务状态和一次性操作过程
* 尚未确认的方案或推测
* Agent 提出但用户没有认可的建议
* 只对当前任务有效的细节
* 认证信息、敏感信息或其他不应长期保存的内容

没有高质量内容时，不生成记忆。

## 长期偏好

一次性的格式、语气、长度或实现要求，不属于长期偏好。

只有满足以下情况之一，才可以保存为 `preference`：

* 用户明确要求今后持续采用
* 用户明确要求记住
* 用户在多个任务中稳定重复相同偏好
* 该偏好已经持续影响多个相关决策

## 记忆类型

只使用以下类型：

* `decision`：已经确认的决策或设计取舍
* `preference`：长期稳定的工作偏好
* `issue-solution`：经过验证的问题解决方式
* `pattern`：可以复用的方法或处理模式
* `constraint`：长期有效的环境、平台或项目限制

每条记忆只选择一个最能表达其核心价值的类型，不得自行创建新类型。

## 查找与比较

处理候选记忆前，先在当前逻辑工作空间中搜索相关记忆。

可以根据以下信息搜索：

* 核心对象
* 标题关键词
* 记忆类型
* 标签
* 关键条件或限制

优先读取疑似相关的记忆条目。

当搜索结果不足以判断，或工作空间记忆文件较小时，可以读取完整文件。

比较时重点判断：

* 核心结论是否相同
* 适用边界是否相同
* 新内容是否提供了实质补充
* 新结论是否明确替代旧结论

标题或标签只能帮助定位，不能单独作为重复判断依据。

## 处理方式

### 跳过

候选内容与已有记忆的核心结论和适用边界相同，且没有新增验证、限制或复用价值时：

* 不创建新记忆
* 不修改原记忆
* 在执行结果中计入跳过

### 更新

候选内容与已有结论一致，但提供了实质补充时，更新已有记忆。

有效补充包括：

* 新的验证来源
* 更明确的适用边界
* 新的限制条件
* 有价值的补充说明
* 在其他工具或环境中的验证结果

更新时：

* 保留原有有效信息和来源
* 合并新增内容
* 删除重复表达
* 不创建高度相似的新记忆

如果新内容只增加来源，不改变结论和边界，只追加来源即可。

### 新增

候选内容具有独立价值，与已有记忆不存在实质重复，也不替代已有结论时，创建新的记忆。

一条记忆只表达一个独立结论。

### 替代

新结论已经确认，并明确推翻或取代旧结论时：

* 创建新的有效记忆
* 新记忆指向被替代的旧记忆
* 旧记忆标记为已替代
* 保留旧记忆正文和来源

不得直接删除或覆盖旧记忆。

### 不写入

出现以下情况时，不进入长期记忆：

* 当前会话没有形成最终结论
* 新旧内容存在尚未解决的冲突
* 解决方式尚未验证
* 适用范围无法确定
* 事实来源不可靠
* 内容只对当前任务临时有效

可以在执行结果中说明未写入原因，但不得将其保存为待确认记忆。

## 记忆表达

每条记忆使用结论式标题和简洁正文，不记录完整讨论过程。

正文应保留：

* 最终结论
* 理解结论所必需的原因
* 适用范围和成立条件
* 必要的环境、平台或版本限制

整理时：

* 删除口语、重复和无关背景
* 合并相同事实
* 保持客观，不补充对话中没有的信息
* 不将推测改写为确定事实
* 不为满足格式而强行补充不存在的限制
* 不得为了简短而删除决定结论是否成立的重要条件

记忆必须能够脱离原始会话独立理解。
