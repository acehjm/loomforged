# Memory Distill

从碎片化、不连续的人机协作过程中，提炼少量真正有长期价值的工程经验，并沉淀到 Global Memory。

Memory Distill 不保存对话记录，而是将已经形成的结论、方法、决策和实践整理为可复用的工程经验。

## 使用场景

当当前工作形成以下内容时执行：

- 已解决的问题，并形成可复用的解决方式。
- 已确定的方案，并明确了设计取舍。
- 已验证的方法，并可以迁移到类似场景。
- 长期有效的约束或实践经验。

也可以主动检查当前任务是否产生值得沉淀的工程经验。

## 核心原则

Memory 保存长期可复用的工程经验，而不是原始对话过程。

沉淀时应保留最终结论、关键原因、适用范围、成立条件和可迁移的方法，删除讨论过程、临时想法、无关背景和一次性细节。

Memory 的价值在于降低未来分析成本、辅助设计决策、避免重复踩坑或形成可复用方法，而不是增加记录数量。

## 执行流程

### 1. 发现候选经验

从当前工作上下文中识别已经形成价值的内容，包括已解决的问题、已确认的决策、已验证的方法、可复用的实践模式和长期有效的约束。

不要保存尚未形成结论的讨论或探索过程。

### 2. 提炼经验

将候选内容转换为独立的工程经验，使其脱离当前对话后仍然可以被理解和使用。

提炼时应去除当前任务无关信息，同时保留影响结论成立的重要条件。

### 3. 判断是否沉淀

根据 `memory-policy.md` 判断候选内容是否具有长期复用价值。

不满足条件时跳过，不修改 Global Memory。

### 4. 检查已有 Memory

写入前检查已有相关 Memory，判断是否存在重复内容，并按照 `memory-policy.md` 决定新增、更新、替代或跳过。

### 5. 保存 Memory

按照 `storage.md` 定义的格式更新 Global Memory。

写入时保留真实来源、适用范围和成立条件，避免加入无关上下文。

## 输出结果

完成后简要说明沉淀结果：

```text
Memory Distill 完成

新增：
xxx

更新：
xxx

跳过：
xxx（原因）
```

如果没有发现值得沉淀的内容：

```text
本次未发现适合长期沉淀的工程经验，Global Memory 未发生变化。
```

## 约束

`memory-distill` 负责将当前工作中的高价值内容提炼为长期工程经验，不保存普通对话、临时信息或未经验证的结论。

不得为了增加 Memory 数量而降低质量标准。
