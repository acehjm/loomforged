# Memory Distill

从碎片化、不连续的人机协作过程中，提炼少量真正有长期价值的工程经验，并沉淀到 Experience 库。

Memory Distill 不保存对话记录，而是将已经形成的结论、方法、决策和实践整理为可复用的工程经验。

## 使用场景

当当前工作形成以下内容时执行：

- 已解决的问题，并形成可复用的解决方式。
- 已确定的方案，并明确了设计取舍。
- 已验证的方法，并可以迁移到类似场景。
- 长期有效的约束或实践经验。

也可以主动检查当前任务是否产生值得沉淀的工程经验。

## 核心原则

Experience 保存长期可复用的工程经验，而不是原始对话过程。

沉淀时应保留最终结论、关键原因、适用范围、成立条件和可迁移的方法，删除讨论过程、临时想法、无关背景和一次性细节。

Experience 的价值在于降低未来分析成本、辅助设计决策、避免重复踩坑或形成可复用方法，而不是增加记录数量。

## 两种模式

### 默认模式：当前会话

只从当前对话窗口中已有的内容提取经验。不读取任何外部文件，不扫描历史会话。

适用于日常工作中随时沉淀经验。

### 项目模式：全量历史会话

当用户明确要求时（如"提取项目所有会话"、"扫描历史会话"、"项目级提取"），扫描该项目的所有历史会话。

执行前必须先确认：用户是否明确要求了项目级提取？如果没有，只使用默认模式。

## 默认模式流程

### 1. 发现候选经验

从当前对话上下文中识别已经形成价值的内容，包括已解决的问题、已确认的决策、已验证的方法、可复用的实践模式和长期有效的约束。

不要保存尚未形成结论的讨论或探索过程。

### 2. 提炼经验

将候选内容转换为独立的工程经验，使其脱离当前对话后仍然可以被理解和使用。

提炼时应去除当前任务无关信息，同时保留影响结论成立的重要条件。

### 3. 判断是否沉淀

根据 `memory-policy.md` 判断候选内容是否具有长期复用价值。

不满足条件时跳过，不修改 Experience。

### 4. 检查已有 Experience

写入前检查已有相关 Experience，判断是否存在重复内容，并按照 `memory-policy.md` 决定新增、更新、替代或跳过。

### 5. 保存 Experience

按照 `storage.md` 定义的格式更新 Experience。

写入时保留真实来源、适用范围和成立条件，避免加入无关上下文。

## 项目模式流程

仅在用户明确要求项目级提取时执行。

### 1. 收集历史会话

获取当前项目下所有历史会话的内容。具体如何访问会话存储，由当前 Agent 平台自行决定。

### 2. 去重

在 Experience 根目录（与 `index.md` 平级）维护 `scan-state.json`，按项目记录上次全量扫描的时间戳：

```json
{
  "projects": {
    "<project-name>": "2026-07-15T10:00:00"
  }
}
```

去重规则：比较每个会话文件的最后修改时间（mtime）与 `lastFullScan`——只处理 `mtime > lastFullScan` 的会话。会话被修改过（如继续对话产生新内容）则 mtime 更新，下次自动纳入扫描，解决续接漏扫问题。

默认模式不读取也不更新 `scan-state.json`。

### 3. 扫描策略

- 跳过纯管理类会话（只有 skill 加载、权限配置等元操作，无实质工程内容）
- 大体积会话优先提取用户消息了解主题，再定向读取涉及结论、方案、修复的部分

### 4. 进入提炼流程

对收集到的内容，按默认模式流程 1-5 执行发现、提炼、判断、检查、保存。

完成后更新 `scan-state.json` 中该项目的 `lastFullScan` 为当前时间（即扫描完成时刻）。

```text

新增：

更新：

```

项目模式：
```text

xxx

```

如果没有发现值得沉淀的内容：
```text
本次未发现适合长期沉淀的工程经验，Experience 未发生变化。
```

## 约束

`memory-distill` 负责将当前工作中的高价值内容提炼为长期工程经验，不保存普通对话、临时信息或未经验证的结论。

不得为了增加 Experience 数量而降低质量标准。
