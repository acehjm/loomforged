# Memory Policy

定义候选 Memory 的价值判断规则，以及已有 Memory 的处理方式。

候选内容由 `memory-distill` 识别，存储格式按照 `storage.md` 执行。

## 核心原则

Global Memory 只保存长期可复用的工程经验，不保存完整对话、临时信息或一次性内容。

Memory 的价值在于帮助未来任务降低分析成本、辅助决策和复用实践经验。

## 准入条件

候选 Memory 满足以下条件时，可以进入 Global Memory：

- 已形成明确结论，而不是讨论过程。
- 脱离原始上下文后仍然可以理解。
- 未来类似任务中具有复用价值。
- 可以说明适用范围或成立条件。

不满足以上条件的内容不进入长期 Memory。

## 不保存内容

以下内容不得进入 Global Memory：

- 普通问答或聊天记录。
- 临时需求和一次性操作。
- 未验证的方案猜测。
- 未形成结论的探索过程。
- 仅适用于单次场景且无法迁移的细节。
- 敏感信息或认证信息。

## 判断原则

Agent 可以主动识别当前工作中形成的高价值经验，不要求用户明确提出保存。

但是：

- 推测不能作为确定经验。
- 建议不能作为实践结论。
- 未验证方案不能作为解决方式。
- 多个未决方案不能作为最终决策。

只有已经确认、验证或形成稳定实践方式的内容，才适合作为 Memory。

## Memory 类型

Memory 使用以下类型之一：

- `decision`：已确认的设计决策或方案取舍。
- `preference`：长期稳定的工作偏好。
- `issue-solution`：经过验证的问题解决方式。
- `pattern`：可复用的方法、流程或处理模式。
- `constraint`：长期有效的环境、平台或业务限制。

每条 Memory 只选择一个最匹配的类型。

## Memory 处理

写入前检查已有相关 Memory，比较核心结论、适用范围和成立条件，避免创建重复或低价值内容。

### 跳过

以下情况不创建新 Memory：

- 与已有 Memory 表达相同结论。
- 仅调整表达方式，没有新增价值。
- 当前内容不足以形成独立经验。

### 更新

以下情况更新已有 Memory：

- 原有结论仍然有效。
- 新内容补充了原因、边界条件或验证结果。

更新时保留已有有效内容，合并新增价值，不创建高度相似的新 Memory。

### 新增

以下情况创建新的 Memory：

- 形成独立结论。
- 与已有 Memory 不存在实质重复。
- 对未来任务具有独立参考价值。

### 替代

以下情况替代已有 Memory：

- 新结论明确推翻旧结论。
- 原经验已经不再适用。

处理时保留旧 Memory，并标记替代关系，不直接删除历史内容。

## Memory 表达

一条 Memory 只表达一个独立结论。

标题应直接表达核心经验，正文保留必要的结论、原因、适用范围和成立条件。

删除讨论过程、重复背景和无关上下文，不得为了简短而删除影响结论成立的重要信息。
