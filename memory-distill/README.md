# Memory Distill

我们跟 AI 的对话是碎片化、不连续、质量不稳定、真正有价值的内容是少数。Memory Distill 的目标不是建立复杂的记忆系统，而是把一次次会话中少量、高质量、可复用的真正有价值的内容，整理成可以长期复用的工作记忆，形成复利工程。

它不会保存完整对话记录，也不会把每次对话都总结一遍，而是关注那些以后还可能用到的内容。简单来说，它要做的是：「这次聊完之后，有什么值得留下来，方便以后继续使用？」

## 为什么要单独做这套记忆

Codex、Claude Code、Craft Agents 等工具都有自己的项目、会话或上下文管理方式，但这些都是跟工具绑定。

我们同时使用多个 Agent 工具时，产生的内容就会彼此独立。这个 Skill 可以：

- 整合不同工具中的记忆，不依赖工具和会话长期存在
- 只保留已经确认、能够复用、具有长期价值的内容
- 为后续知识沉淀提供基础，经过持续使用验证后，可以发布到个人知识库、行业知识库、项目经验库

## 它是怎么工作的

Memory Distill 会从当前会话中提取候选记忆，并与已有记忆进行比较。

根据实际情况，它会：

* 跳过已经存在的重复内容
* 将新的有效信息补充到已有记忆
* 新增一条独立记忆
* 用新结论替代已经过时的旧结论
* 跳过尚未确认或价值不高的内容

没有值得沉淀的内容时，它不会修改记忆库。

## 目录结构

Skill 包含三个文件：

```text
memory-distill/
├── SKILL.md            # 定义整体执行流程
├── memory-update.md    # 判断什么值得记，以及如何更新已有记忆
└── storage.md          # 定义记忆保存位置、文件格式和索引规则
```

全局记忆库需单独维护，例如：

```text
global-memory/
├── index.md
└── memory/
    ├── 文旅安防知识库--39bc7a.md
    ├── code-scribe--42af81.md
    └── 高校安防知识库--a72f30.md
```

一个项目或主题对应一个记忆文件（也就是 Skill 中的逻辑工作空间），不同时间、不同会话或不同工具中的同一个项目，也可以持续写入同一份记忆。

## 使用前配置

在 `storage.md` 中配置全局记忆根目录：

```text
GLOBAL_MEMORY_ROOT: D:\Knowledge\global-memory
```

这个目录需要提前创建，如果不存在或者无法访问，Skill 就会停止执行，不会在其他位置自行创建记忆库。

## 如何使用

可以告诉 Agent：

- 沉淀一下本次会话的有效记忆。
- 把刚才确认的方案保存到当前项目记忆中。
- 整理这次问题处理过程中值得以后复用的经验。
- 检查一下本次会话有没有值得长期保存的内容。

也可以使用斜杠命令直接触发。

## 执行结果

执行完成后，Skill 只返回简单结果，例如：

```text
记忆沉淀完成：

- 工作空间：field-notes（ws-39bc7a）
- 新增：2 条
- 更新：1 条
- 替代：0 条
- 跳过：3 条
```

如果没有值得保存的内容：

```text
本次会话未发现适合长期沉淀的高质量内容，未修改全局记忆。
```

## 能力边界

Memory Distill 只负责沉淀当前会话。

它不负责：

* 搜索其他项目的历史记忆
* 修复损坏的全局索引
* 自动将记忆整理到个人知识库
* 保存或恢复完整会话

跨项目查找和引用历史记忆，可以通过另外一个记忆检索 Skill `memory-recall` 完成。
