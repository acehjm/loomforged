# Field Notes

将任意碎片信息整理为逻辑清晰、可长期维护的结构化内容。

重点是**整理信息**，而不是改写、总结或重新创作。

默认在对话中输出整理结果。

当用户要求保存、写入、输出或导出到指定平台时，必须先读取并执行对应的 `<platform>-export.md`。

平台导出仅调整平台要求的输出格式，不重新整理、补充、优化或改写正文内容。

---

# 使用场景

适用于整理：

- 项目沟通记录
- 会议记录
- 需求讨论
- 调研记录
- 聊天记录
- 现场笔记
- 其他碎片信息

---

# 整理原则

始终遵循以下原则：

- 保留全部有效信息
- 去除重复内容和口语表达
- 合并相同主题的信息
- 保持原始含义
- 保持客观，不增加输入中不存在的事实
- 以内容逻辑组织信息，而不是机械保持输入顺序。

允许：

- 指代消解
- 上下文补全
- 合理归类相关内容

不要：

- 推测业务逻辑
- 补充不存在的需求
- 增加设计方案
- 扩写原始内容

---

# 信息整理

整理时应先整体理解内容，再提取有效信息，按主题或逻辑关系重新组织结构，最后输出整理结果。

不要边阅读边输出。

完成整体理解后，再组织内容。

---

# 内容组织

根据内容自然组织结构。

优先按主题组织。

如果存在明确的业务流程、时间顺序或因果关系，可按照相应顺序组织。

要求：

- 同一主题集中表达
- 相近内容相邻组织
- 保持逻辑连续
- 避免重复章节
- 标题简洁明确

文档结构应由内容决定，而不是由固定模板决定。

不要为了保持格式增加无意义的章节。

---

# 信息保留

整理时应突出关键信息，尤其包括：

- 决策
- 需求
- 约束条件
- 风险
- 状态变化
- 时间节点
- 待办事项
- 人员分工（如果存在）

删除重复表达、寒暄内容、无意义语气词及与主题无关的信息。

---

# 推断原则

原则上不推断。

仅当输入存在明显缺失，且补充说明能够提高可读性时，可进行适度说明。

所有推断内容必须明确标记为 Agent 建议。

推断不得改变原始含义。

---

# 写作风格

使用简洁、客观、结构化的表达。

根据内容特点选择最合适的 Markdown 表达方式，灵活使用标题、列表、表格等形式，以提升可读性。

避免连续的大段文字，一个主题聚焦一个中心内容，不机械套用固定模板。

---

# 最终检查

输出前确认：

- 信息完整、无遗漏
- 逻辑关系正确
- 层次清晰
- 保持原始含义
- 所有推断均已标记
