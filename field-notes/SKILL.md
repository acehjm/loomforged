# Field Notes

将各种碎片信息整理为有条理、有逻辑、易于阅读的内容。

重点是**整理信息**，而不是改写、总结或重新创作。

默认直接在对话中输出整理后的内容。

如用户要求导出到指定平台，应按照对应的 `<platform>-export.md` 执行导出。

---

# 使用场景

适用于整理：

- 项目沟通记录
- 会议记录
- 需求讨论
- 调研记录
- 聊天记录
- 现场笔记
- 其他碎片信息

---

# 工作目标

输出结果应满足：

- 信息完整
- 逻辑清晰
- 层次自然
- 易于阅读
- 忠实于原始内容

整理后的内容应帮助读者快速理解原始信息，而不是改变原始信息。

---

# 整理原则

始终遵循以下原则：

- 保留全部有效信息
- 去除重复内容和口语表达
- 合并相同主题的信息
- 保持原始含义
- 保持客观，不增加输入中不存在的事实
- 整理信息，而不是记录输入顺序

允许：

- 指代消解
- 上下文补全
- 合理归类相关内容

不要：

- 推测业务逻辑
- 补充不存在的需求
- 增加设计方案
- 扩写原始内容

---

# 信息整理

整理时遵循以下过程：

1. 理解整体内容
2. 提取有效信息
3. 去除重复内容
4. 合并相关主题
5. 调整表达顺序
6. 输出整理结果

不要边阅读边输出。

完成整体理解后，再组织内容。

---

# 内容组织

根据内容自然组织结构。

优先按主题组织。

如果存在明确的业务流程、时间顺序或因果关系，可按照相应顺序组织。

要求：

- 同一主题集中表达
- 相近内容相邻组织
- 保持逻辑连续
- 避免重复章节
- 标题简洁明确

文档结构应由内容决定，而不是由固定模板决定。

不要为了保持格式增加无意义的章节。

---

# 信息保留

优先保留：

- 决策
- 需求
- 约束条件
- 风险
- 状态变化
- 时间节点
- 待办事项
- 人员分工（如果存在）

删除：

- 重复表达
- 寒暄内容
- 无意义语气词
- 与主题无关的信息

---

# 推断原则

原则上不推断。

仅当输入存在明显缺失，且补充说明能够提高可读性时，可进行适度说明。

所有推断内容必须明确标记为 Agent 建议。

推断不得改变原始含义。

---

# 写作风格

使用简洁、客观、结构化的表达。

要求：

- 优先使用短句
- 优先使用列表
- 避免长段文字
- 同一级内容保持一致的表达方式
- 一个主题表达一个中心内容

整理后的内容应自然流畅，而不是机械套用模板。

---

# 最终检查

输出前确认：

- 信息完整
- 无重复内容
- 无遗漏重要信息
- 逻辑关系正确
- 层次清晰
- 原始含义保持一致
- 所有推断均已标记
