
#### Obsidian

当用户明确要求以下行为时，使用本规范：

- 输出到 Obsidian
- 保存到 Obsidian
- 写入 Obsidian
- 创建 Obsidian 笔记
- 生成 Obsidian 文档

本规范仅负责将最终 Markdown 保存到 Obsidian，不负责信息整理。

---

#### 执行规则

使用本规范时，必须：

1. 创建 Markdown 文件。
2. 将最终 Markdown 内容写入文件。
3. 保存到指定目录。
4. 在对话中返回最终文件路径。

不要仅在对话中输出 Markdown。

如果无法创建文件，必须说明原因，并输出完整 Markdown 内容。

---

#### 保存位置

默认保存到：

```text
E:\资料\内容仓库\Contents\FieldNotes\
```

如果用户指定保存目录，则优先使用用户指定目录。

---

#### 文件命名

使用以下格式：

```text
FN-YYYYMMDD-类型-主题.md
```

例如：

```text
FN-20260612-沟通-AI及消防提升.md
FN-20260618-需求-考勤业务需求交流.md
```

要求：

- 文件名简洁、明确。
- 使用 `.md` 扩展名。
- 不使用 Windows 非法文件名字符。

创建文件前检查是否存在同名文件：

- 不存在：直接创建。
- 已存在：自动追加 `-01`、`-02`、`-03`……，使用第一个可用文件名。
- 不覆盖已有文件。

---

#### Frontmatter

文件开头必须使用 YAML Frontmatter：

```yaml
---
项目:
日期:
类型:
tags:
---
```

要求：

- 使用合法 YAML。
- 不输出空字段。
- `日期` 使用 `YYYY-MM-DD`。
- `类型` 与文件名保持一致。
- `tags` 使用 YAML 数组。
- `项目` 优先从内容中提取，如果为空或无法确定，则保持为空，不得推断或编造。

---

#### Markdown 要求

使用标准 Markdown。

要求：

- 使用四级、五级、六级标题。
- 保持格式统一、内容简洁、自然、易读。
