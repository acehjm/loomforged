#### Obsidian

当用户明确要求以下行为时，使用本规范：

- 输出到 Obsidian
- 保存到 Obsidian
- 写入 Obsidian
- 创建 Obsidian 笔记
- 生成 Obsidian 文档

本规范仅负责 Obsidian 导出，不负责信息整理。

---

#### 执行规则

使用本规范时，必须：

1. 创建 Markdown 文件。
2. 将整理后的内容写入文件。
3. 保存到指定目录。
4. 在对话中返回最终文件路径。

不要仅在对话中输出 Markdown。

如果无法创建文件，必须说明原因，并输出完整 Markdown 内容。

---

#### 保存位置

默认保存到：

```text
E:\资料\内容仓库\Contents\FieldNotes\
```

如果用户指定保存目录，则优先使用用户指定目录。

---

#### 文件命名

必须使用以下格式：

```text
FN-YYYYMMDD-客户简称-主题.md
```

例如：

```text
FN-20260612-XX用户-AI及消防提升沟通.md
FN-20230203-XX客户-智慧园区功能确认会议.md
```

要求：

- 必须包含日期、类型 和主题。
- 使用 `.md` 扩展名。
- 主题保持简短、明确。
- 不使用“整理”“笔记”“会议记录”等无意义名称。
- 不使用 Windows 非法文件名字符。

`类型` 推荐取值：

- 沟通
- 会议
- 需求
- 调研
- 实施
- 测试
- 问题
- 跟进
- 随手记

##### 防覆盖

创建文件前必须检查目标目录。

- 不存在同名文件：直接创建。
- 已存在同名文件：自动追加 `-01`、`-02`、`-03`……
- 使用第一个不存在的文件名。
- 禁止覆盖已有文件。

---

#### Frontmatter

使用 YAML Frontmatter：

```yaml
---
项目:
日期:
类型:
tags:
---
```

要求：

- 使用合法 YAML。
- 不输出空字段。
- `日期` 使用 `YYYY-MM-DD`。
- `类型` 与文件名保持一致。
- `tags` 使用 YAML 数组。

---

#### Obsidian 特性

##### Checklist

待办事项使用：

```markdown
- [ ] 待办事项
```

##### Callout

推断内容使用：

```markdown
> [!tip] Agent 建议
> 以下内容基于上下文推断，请确认是否准确。
```

风险使用：

```markdown
> [!warning] 风险
> ...
```

##### Wiki Link

引用笔记：

```markdown
[[页面名称]]
```

引用图片：

```markdown
![[image.png]]
```

---

#### 输出要求

- 使用标准 Markdown。
- 使用四级、五级、六级标题。
- 不使用一级、二级、三级标题。
- 保持内容简洁、自然、易读。
- 优先保证内容质量，不为了格式增加无意义元素。
