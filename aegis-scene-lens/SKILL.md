# Aegis SceneLens：安防业务场景透镜

以“场景复原”为主线，把零散需求还原成可讨论、可验证的业务场景。默认只完成核心分析；技术、政策、AI、PoC 和正式报告按需展开。

## 分支选择

始终执行步骤 1–3，再根据用户目的选择步骤 4 的支线：

- **默认核心分析**：用户只提供需求或要求梳理业务时，到步骤 3 后输出一页式场景地图。无需联网研究。
- **行业/政策研究**：用户明确要求政策、标准、行业背景，或关键结论依赖可能变化的外部事实时，读取 [research.md](references/research.md)。
- **AI/可行性/PoC**：用户要求判断 AI，或当前决策依赖 AI 适用性、落地条件、可行性或验证方案时，读取 [ai-feasibility.md](references/ai-feasibility.md)。只执行被问到的部分。
- **正式深研报告**：用户明确要求深度研究、可研、立项材料或正式报告时，读取 [deep-report.md](references/deep-report.md)，并加载报告所需的上述支线。

信息不足不阻断分析。先用显式假设推进，只提出会改变场景边界、风险、责任或结论的问题，每轮最多 5 个。

## 1. 需求复原

保留原始片段，逐条提取业务对象、动作、目标、场所、角色和约束。判断片段关系：同场景、上下游、包含、冲突、独立或无法确认。按照“对象 + 动作 + 目标 + 场所/流程阶段”形成候选场景；证据不足的片段保持未归属，不强行合并。

将内容标为：

- `已知`：用户原文或可靠材料明确表达。
- `推断`：有依据但原文未直接表达。
- `假设`：为继续分析暂时采用。
- `未知`：当前无法安全判断。

**完成条件**：每个原始片段都已归入候选场景或标为未归属；片段关系、依据和置信度可追溯。

## 2. 场景定界

为每个候选场景明确：

- 行业、地域、场所和时间边界。
- 责任角色、参与角色和业务对象。
- 要改变的业务结果。
- 风险事件、诱因、后果和现有控制。
- 当前痛点、约束及成功标准。

区分场景、业务需求与实现手段。把“增加摄像机”“开发算法”“建设平台”等技术化表述向上还原为它要支持的业务动作和结果。

**完成条件**：每个场景都有清晰边界、责任主体、业务目标和核心风险；缺失项已显式标记。

## 3. 业务建模

先描述现状流程，再建立风险和处置闭环：

```text
诱因 → 风险事件 → 可观察信号 → 发现 → 核实 → 分级
→ 通知/派单 → 处置 → 关闭 → 复盘
```

补充误报、漏报、设备离线、网络中断、无人响应和争议处理等例外。为关键环节明确责任人、输入、输出、时限和留痕要求。只有识别或告警、没有责任和处置动作的场景属于开环。

用结果导向句式重述需求：

> 当【风险/触发条件】发生时，【责任角色】需要在【时限】内获得【信息或能力】，执行【业务动作】，达到【可衡量结果】，同时满足【约束】。

从业务动作推导所需能力，并按 `必须具备`、`应该具备`、`可选增强`、`暂不纳入` 排序。人员、制度、物理防护、规则、传感器、软件和 AI 都是候选实现方式。

**完成条件**：每个关键风险都有责任角色、业务动作、闭环结果和验证指标，或被明确列为待解决缺口。

## 4. 按需深研

只进入已触发的支线，并执行对应参考文件中的完成条件。先完成场景复原，再研究政策或判断技术，避免围绕尚未定界的问题扩散调研。

## 默认输出

核心分析保持一页式摘要：多个场景优先用一张表，每个场景只给定义、核心风险、目标闭环和关键缺口；详细流程、能力清单和指标目录留到用户选择某个场景继续深入时再展开。使用以下结构，按实际内容合并空章节：

1. **需求片段关系**：候选分组、冲突、独立项和未归属项。
2. **场景理解**：边界、角色、对象、目标、风险及当前控制。
3. **业务闭环**：现状问题、目标流程、责任和能力需求。
4. **已知与未知**：事实、推断、假设及会改变结论的信息。
5. **下一步**：优先验证的 1–5 项事项。

单一、连续且边界清楚的需求无需展示片段关系表。先给业务结论，再给分析依据。除非用户要求正式报告，默认回答控制在约 800–1200 个汉字，不逐场景生成完整需求书。

## 分析范围

聚焦行业、场景、业务、风险、能力、证据和验证。输入中的实现信息只作为现状背景，输出围绕业务问题、业务闭环和验证条件展开。

提交前确认：每个原始片段有去向；场景与技术已分开；关键风险形成闭环；事实与假设已区分；输出只包含用户当前决策所需的深度。
