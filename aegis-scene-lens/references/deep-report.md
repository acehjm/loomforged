# 深度场景研究报告

仅在用户明确要求深度研究、可研、立项材料或正式报告时使用。根据任务加载行业/政策或 AI/可行性支线；没有触发的章节从报告中删除。

## 报告结构

### 1. 一页结论

- 场景重述、问题本质和最重要的三项发现。
- 可行性及置信度；若未要求可行性则省略。
- 优先行动，不超过 5 项。

### 2. 输入与边界

- 原始片段、候选分组及片段关系。
- 行业、地域、组织、场所、对象和分析基准日期。
- 已知、推断、假设、未知和明确不在范围内的事项。

### 3. 行业与政策

解释与决策相关的行业机制、风险来源和政策影响。仅在触发研究支线时保留；引用原始来源并说明日期、状态和适用范围。

### 4. 场景与业务

- 角色、对象、目标、风险、现有控制和失效点。
- 现状流程、目标流程和例外流程。
- 责任、时限、输入、输出和留痕要求。

### 5. 能力需求

| 优先级 | 业务能力 | 支持的动作 | 责任角色 | 验证指标 |
|---|---|---|---|---|
| 必须/应该/可选/暂不纳入 |  |  |  |  |

### 6. AI 与替代方案

仅在触发 AI 支线时保留。说明适用性、成立条件、错误成本、独立控制及流程、物理、规则、传感器或人工等替代方式。

### 7. 可行性与 PoC

仅在触发可行性或验证支线时保留。逐维度列出结论、证据、缺口、前置条件和置信度；单列否决项。需要 PoC 时给出业务假设、范围、基线、指标和决策门。

### 8. 路径、风险与待确认项

- 按阶段列目标、依赖、产出和决策门。
- 只列会改变结论或实施路径的风险和问题。
- 说明下一步获取证据的方式和责任角色。

### 9. 来源与局限

列明来源标题、发布机构、日期、链接和检索日期；说明数据口径、适用范围、现场证据缺口及不能作出的承诺。

## 写作要求

先给答案，再给证据。每个章节服务于用户当前决策；没有内容或未触发的章节直接删除。图表和数字必须来自结构化数据或可靠来源，推断不得伪装成事实。

**完成条件**：报告回应用户的决策问题；每个结论能追溯到需求片段、公开证据或显式假设；未触发的支线没有进入报告。
