# Code Scribe

Code Scribe 是一个面向源码项目的业务知识提取（Business Knowledge Extraction）Skill。

它通过分析源码，提取项目的业务知识，并生成帮助工程师快速理解和接手项目的 README 或业务文档。

与传统 README 生成工具不同，Code Scribe 的目标不是整理源码目录或生成接口文档，而是帮助工程师回答：

- 这个项目做什么？
- 业务从哪里进入？
- 核心流程如何运行？
- 哪些规则、边界或数据变化决定业务结果？
- 哪些外部系统、配置或协作机制参与业务？

README 只是知识交付形式，真正目标是建立完整、准确、可验证的业务认知。

---

# 设计理念

Code Scribe 采用 **Business First** 原则。

整个分析过程始终围绕业务展开，而不是围绕源码结构展开。

所有结论必须能够从源码验证，不依赖经验推测。

整个工作流分为三个阶段：

```text
Source Code
      │
      ▼
 Analysis
      │
      ▼
Presentation
      │
      ▼
 Quality
```

三个阶段职责明确：

| 阶段 | 职责 |
|------|------|
| Analysis | 从源码提取并验证业务事实，建立业务事实池 |
| Presentation | 将业务事实组织为工程师易于理解的 README |
| Quality | 评审 README 是否真正帮助工程师理解项目 |

三个阶段相互独立：

- Analysis 不负责组织 README。
- Presentation 不新增事实。
- Quality 不补充推测内容。

如果质量评审发现事实不足，应返回 Analysis，而不是直接修改 README。

---

# 能力

Code Scribe 可以帮助完成：

- 快速理解陌生源码项目
- 快速接手已有项目
- 梳理项目整体业务
- 提取业务入口
- 梳理核心业务流程
- 分析业务规则与边界
- 分析数据流转
- 分析外部系统协作
- 生成或完善 README
- 从源码沉淀业务文档

生成的 README 聚焦业务理解，而不是技术说明。

---

# 适用项目

Code Scribe 更适用于**业务流程清晰、业务规则较多、系统协作关系明确**的项目。

例如：

- 数据同步系统
- 数据集成平台
- 数据治理平台
- 工作流系统
- 审批流系统
- ERP、MES、WMS、CRM 等业务系统
- 企业中后台系统
- 微服务业务系统
- 第三方平台集成项目
- 消息驱动系统
- 定时任务系统
- 企业内部业务平台

这些项目通常具有以下特点：

- 存在明确业务入口
- 存在完整业务流程
- 包含业务规则、状态或边界
- 涉及数据转换或数据流转
- 与第三方系统存在业务协作

Code Scribe 能够较好地提取这些业务知识，并组织为高质量 README。

---

# 不适用项目

以下项目通常不适合作为 Code Scribe 的主要使用对象：

- 前端页面项目
- UI 展示项目
- CLI 工具
- SDK
- Library
- 通用组件库
- Demo、Sample、Example 项目
- 算法仓库
- LeetCode 类型项目
- 仅包含文档的仓库

这些项目通常缺少完整业务流程，使用 Code Scribe 难以发挥优势。

---

# 不适用场景

以下场景不建议启动 Code Scribe：

- 单个文件分析
- 单个类或函数解释
- Bug 排查
- Debug
- Code Review
- 性能优化
- 安全审计
- 重构建议
- 单元测试分析
- 局部代码问答

这些场景更适合直接进行针对性的代码分析，而不是执行完整的业务知识提取流程。

---

# 输出特点

Code Scribe 生成的 README 不追求信息越多越好，而是帮助工程师快速建立完整业务认知。

README 通常围绕以下内容组织：

- 项目概况
- 业务入口
- 核心业务流程
- 业务规则与边界
- 字段映射
- 重要业务配置
- 重要 API
- 三方 API / 外部对接
- 必要的协作补充

其中：

- 核心业务流程始终作为全文主线。
- 规则、配置、映射优先贴近业务流程表达。
- 低价值实现细节默认省略。
- 所有结论均要求能够从源码验证。

# 方法论

本 Skill 基于四个相互独立的模块协同工作：

| 文件 | 作用 |
|------|------|
| `SKILL.md` | 定义 Skill 的定位、触发条件和整体工作流 |
| `analysis.md` | 定义如何从源码提取和验证业务事实 |
| `presentation.md` | 定义如何组织 README，使业务更易理解 |
| `quality.md` | 定义 README 的交付质量标准 |

这种分层设计实现了分析、组织和验收的解耦，使 Skill 更稳定、更易维护，也便于持续演进。

---

# 设计目标

Code Scribe 不追求生成最长的 README，也不追求覆盖全部源码。

它更关注：

- 帮助工程师快速建立业务认知
- 尽量减少阅读源码的成本
- 保持业务表达准确、克制、可验证
- 生成长期可维护的项目文档

最终，希望工程师仅阅读 README，即可理解项目的大部分核心业务，而无需先阅读大量源码。
