# Code Scribe

从源码中提取、验证并组织业务知识，帮助工程师快速理解和接手已有项目。

核心原则：

> Business First：先理解业务，再组织知识，最后交付结果。

README 只是知识表达形式之一，目标是建立准确、可验证的项目业务认知。

默认在对话中输出结果，如果用户要求导出到指定平台，则按照对应的 `<platform>-export.md` 执行。

---

# 使用场景

当用户希望理解整个源码项目，而不是局部代码时，使用本 Skill。

适用于：

- 理解已有项目业务。
- 快速接手维护项目。
- 梳理核心业务流程、规则和数据流转。
- 从源码生成或完善 README。
- 沉淀项目业务文档。

如果用户提出具体业务问题，但依赖源码上下文，应先完成源码分析，再基于分析结果回答。

---

# 前置条件

必须满足以下条件之一：

- 用户提供源码项目路径。
- 当前目录为源码项目。

如果无法识别源码项目，提示用户提供项目路径或切换到源码目录。

---

# 工作流程

按照以下流程执行：

1. 验证项目有效性。
2. 按照 `analysis.md` 分析源码，提取并验证业务事实。
3. 如果已有信息不足以支撑输出，继续分析源码。
4. 按照 `presentation.md` 组织业务知识。
5. 完成质量检查后交付结果。

---

# 分析原则

始终遵循：

- 业务优先于源码结构。
- 理解优先于覆盖率。
- 准确优先于完整。
- 事实优先于经验。
- 可验证优先于推测。

分析过程围绕：

- 项目解决什么业务问题。
- 核心业务流程如何实现。
- 数据如何流转。
- 系统如何与外部交互。
- 关键规则和边界是什么。

展开。

不要根据源码目录或类结构直接组织文档。

---

# 输出要求

输出应以业务知识为中心，而不是源码说明。

重点描述：

- 项目定位。
- 核心业务流程。
- 业务规则和边界。
- 数据流转。
- 外部系统协作。
- 必要的架构信息。

避免输出：

- 无业务价值的类说明。
- 大量目录介绍。
- 普通枚举和字典说明。
- 仅为了覆盖源码而增加的内容。
