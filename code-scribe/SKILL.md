# Code Scribe

Code Scribe 用于从源码中提取业务知识，帮助工程师快速理解和接手已有项目。

README 只是知识交付形式之一，真正目标是建立完整、准确、可验证的项目业务认知。

整个过程采用 **Business First** 原则：

> 先理解业务，再组织知识，最后验证交付。

整个工作流分为三个阶段：

```text
Analysis
    │
    ▼
Presentation
    │
    ▼
Quality
```

三个阶段职责明确：

- **Analysis**：采集并验证源码事实，建立业务事实池。
- **Presentation**：组织业务事实，生成易于理解的 README。
- **Quality**：验证 README 是否真正帮助工程师理解项目。

三个阶段职责不能混用：

- Analysis 不组织 README。
- Presentation 不新增事实。
- Quality 不补充推测。

任何阶段未完成，不进入下一阶段。

如果质量检查发现事实不足，应返回 Analysis，而不是直接修改 README。

---

# 适用场景

当用户希望理解整个源码项目，而不是局部代码时，应使用本 Skill。

包括但不限于：

- 快速理解已有项目
- 快速接手维护项目
- 梳理项目整体业务
- 理解业务入口
- 梳理核心业务流程
- 理解业务规则、边界、状态变化
- 理解数据流转
- 理解外部系统协作
- 从源码生成或完善 README
- 从源码沉淀业务文档

对于下面这类表达，也应主动启动本 Skill：

- 这个项目是干什么的？
- 帮我分析整个项目。
- 帮我快速接手这个项目。
- 帮我生成 README。
- 帮我完善 README。
- 给这个项目补一份文档。

如果用户既希望理解项目，又提出具体业务问题，应优先完成源码分析，再基于分析结果回答。

---

# 不适用场景

以下情况不应使用本 Skill，而应直接完成对应任务：

- 单个代码文件分析
- 单个函数、类、模块解释
- Bug 排查
- Debug
- Code Review
- 重构建议
- 性能优化
- 安全审计
- 单元测试分析
- 局部代码问答

以下类型项目通常不适合作为本 Skill 的主要使用对象：

- 前端页面项目
- UI 展示项目
- CLI 工具
- SDK
- Library
- 通用组件库
- Demo、Sample、Example 项目
- 算法仓库
- LeetCode 类型仓库

本 Skill 更适用于业务流程较强、系统协作关系明确的源码项目，例如：

- 数据同步
- 数据集成
- 数据治理
- 工作流
- 审批流
- 业务后台
- 中后台系统
- ERP、MES、WMS、CRM 等业务系统
- 微服务业务系统
- 消息驱动系统
- 定时任务系统
- 第三方平台集成
- 企业内部业务系统

# 前置条件

满足以下任一条件：

- 用户提供源码项目路径
- 当前目录为源码项目

如果无法识别为源码项目，则返回：

> 当前目录未识别为源码项目，请提供项目路径或切换到源码目录。

---

# 工作流程

按照以下流程执行：

1. 验证项目有效性。
2. 按照 `analysis.md` 提取并验证业务事实。
3. 如果事实不足以支撑 README 所需信息，继续分析源码。
4. 按照 `presentation.md` 组织业务知识。
5. 按照 `quality.md` 进行交付评审。

如果 Quality 未通过：

- 因事实不足导致的问题，返回 Analysis。
- 因组织表达导致的问题，返回 Presentation。

完成质量评审后，再交付最终结果。

---

# 执行原则

始终遵循以下原则：

- 业务优先于源码结构。
- 理解优先于覆盖率。
- 准确优先于完整。
- 事实优先于经验。
- 可验证优先于推测。

所有结论必须能够从源码确认。

README 只是最终表达，不应驱动分析过程。

分析应始终围绕：

- 项目做什么？
- 为什么得到这个业务结果？
- 源码依据是什么？

展开。

---

# 输出

默认生成项目根目录 `README.md`。

如果项目已有 README，则默认基于最新分析结果覆盖更新；除非用户明确要求保留原文件或生成新的文档。

如果用户并未要求生成 README，而只是希望理解项目，则可以直接输出分析结果，而不必强制生成 README。

如果用户要求导出到指定平台，则按照对应的 `<platform>-export.md` 执行导出。
