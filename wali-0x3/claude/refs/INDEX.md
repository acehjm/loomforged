# 跨项目参考索引

`refs/` 保存随 WALI Agent 一起复用、跨项目成立且低频变化的说明、模板和检查基线。它不是具体项目的知识库，不记录当前进度，也不自动改变 Goal、Spec、Rules 或阶段权限。

本索引只负责告诉 Agent“有什么、谁读取、何时读取”。角色路由是上下文选择约定，不是安全权限；文件存在也不表示当前任务必须使用。

## 1. 内容归属

| 内容 | 放置位置 | 说明 |
| --- | --- | --- |
| 所有会话都必须知道的稳定事实 | `CLAUDE.md` | 保持短小，作为 Agent 入口 |
| 跨项目通用且违反时应阻止交付的硬约束 | `rules/` | 尽量可判定并按路径加载 |
| 跨项目稳定、按角色与场景查阅的资料 | `refs/` | WALI 说明、开发模板、代码检查基线 |
| 跨项目可重复的多步骤方法 | `skills/` | 提供流程，不扩大阶段权限 |
| 用户为具体项目提供的需求、规格、接口、模块和特殊约束 | 项目的 `docs/` | 保留原始输入和来源 |
| 从项目资料与代码事实归一化出的实施和测试契约 | `docs/wali-0x3/spec.md` | 进入 Goal + Spec 联合确认 |

Refs 与项目资料的分界不取决于文件格式，而取决于适用范围。跨多个项目长期复用的 JSON 返回约定、分页格式、错误格式、事件处理模板和企业代码检查基线属于 Refs；只对一个项目成立的接口和模块设计属于该项目 `docs/` 与 Spec。

## 3. Agent 读取约定

Agent 开始任务时读取本索引，只继续加载同时满足以下条件的条目：

1. “读取者”包含当前角色。
2. “何时读取”与当前活动任务匹配。
3. 文件仍存在，且版本和适用范围没有明显冲突。

Developer 读取适用的开发模板和代码检查基线。Reviewer 只读取代码检查与审查资料，不因目录可见而加载 Developer 专用模板。其他角色默认不读取这两个集合，除非索引以后明确增加。

Agent 可直接使用 Read 工具读取 Ref，不需要调用 Skill，不需要写入 `allowed_capabilities`，也不建立 Task → Skill 关系。Ref 仍不能扩大 `write_scope`、允许新的副作用或替代 Spec 的项目判定规则。

## 4. 项目资料流转

```text
用户提供或项目已有的 docs 资料
→ Coordinator 核对来源、版本、缺失、歧义、冲突和代码现状
→ 将当前项目的可执行结论编译进 spec.md
→ Goal + Spec 联合确认
→ 各角色按 Spec 和适用 Ref 工作
```

`spec.md` 应记录项目资料的相对路径、版本或日期、适用范围和采用结论。项目特殊要求不复制到 `refs/`；跨项目 Ref 在本项目存在例外时，只把例外和依据写入 Spec。

## 5. 维护边界

`refs/` 属于低频维护的共享 Agent 资料。新增 Ref 前应确认它能够跨项目复用、有明确读取角色和触发场景，并且不会把一次性项目选择提升成全局惯例。

普通项目迭代只更新获授权的项目 `docs/` 和 WALI 状态。新增或修改共享 Ref 时，更新对应索引，并检查受影响 Agent 的通用读取约定；不需要为每个 Ref 改写 Agent 身份。
