# 跨项目开发模板

本目录保存由 Developer 按场景读取、可跨多个项目复用且低频变化的开发约定与模板。它可以包含格式说明、处理流程、示例和代码骨架，但不保存某个项目的接口文档、模块设计或临时实现决定。

适合放在这里的内容包括：

- 通用 JSON 返回结构。
- 分页请求、响应和边界语义。
- 错误码、错误载荷和异常传播格式。
- 事件信封、生产/消费流程、幂等和重试约定。
- 与上述约定配套的语言无关示例或代码模板。

## 2. 文件组织

单份说明可以直接使用 Markdown 文件：

```text
templates/
├── INDEX.md
├── json-response.md
├── pagination.md
├── error-handling.md
└── event-processing.md
```

需要同时提供多种代码样例时，使用一个自包含目录：

```text
templates/
└── json-response/
    ├── INDEX.md
    ├── contract.md
    ├── example.java
    └── example.ts
```

目录内的 `INDEX.md` 说明规范语义、适用与不适用场景、文件用途和验证方式。代码只是模板，不得被 Agent 不加判断地复制。

## 3. 扩展步骤

1. 确认内容跨项目成立，不依赖某个项目的业务或模块结构。
2. 定义稳定 `REF-TPL-*` 标识、版本、适用场景和不适用场景。
3. 写清正常路径、失败路径、边界语义和需要保持的兼容性。
4. 示例代码尽量最小，并说明调用方仍需根据项目技术栈适配。
5. 在本文件登记新条目；新增模板不要求修改 Developer 定义。
6. 若具体项目需要偏离模板，只在该项目 Spec 记录差异和依据，不修改共享模板迁就单个项目。

## 4. Developer 使用方式

Developer 先通过上级 `refs/INDEX.md` 和本索引判断当前任务是否匹配，再读取最小相关文件。模板提供实现起点，不替代已确认 Spec、项目代码事实或测试判定规则。

未匹配当前任务的模板不加载。模板过期、与 Spec 冲突或无法适配真实代码时，停止套用并交给 Coordinator 澄清。
