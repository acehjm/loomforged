# 企业代码检查基线

本目录保存跨项目复用、低频变化的企业内部代码检查要求和审查清单。这里的“合规”只指代码质量、安全和企业工程约定，不指法规资料，也不保存某个项目临时增加的检查条件。

同一份基线面向两个角色：

- Developer 在实现与交接前用于自检和记录证据。
- Reviewer 在独立审查时用于发现问题、分级并记录到 `issues.md`，默认不直接修复。

## 2. 内容边界

适合放入本目录：

- 跨项目代码检查条款及严重程度。
- 禁止模式与允许例外的判定条件。
- Developer 自检清单。
- Reviewer 独立审查清单。
- 确定性的静态检查命令或结果解释。

不适合放入本目录：

- 单个项目的业务规则、接口和模块约束。
- 当前 Goal 的临时检查命令或验收状态。
- 某次审查发现、豁免决定或执行证据。

项目特殊条款、例外和适用范围写入该项目 Spec；运行命令和结果写入 Goal、Task、Issue 或 handoff。

## 3. 扩展步骤

1. 确认检查要求跨项目适用，并明确适用语言、文件类型或技术条件。
2. 定义稳定 `REF-COMP-*` 标识、版本、严重程度模型和通过条件。
3. 分开“必须修复”“需要说明”和“建议改进”，避免把风格偏好当成阻断问题。
4. 同时说明 Developer 如何自检、Reviewer 如何独立复核，以及证据应记录在哪里。
5. 在本文件登记新条目；新增基线不要求修改 Developer 或 Reviewer 定义。
6. 基线升级时保留变更依据，并检查已有项目是否需要在 Spec 中声明兼容或例外。

## 4. 角色使用方式

Developer 和 Reviewer 通过上级 `refs/INDEX.md` 与本索引选择当前代码适用的最小检查集合。其他 Agent 默认不读取本目录。

这些文件是共享检查依据，不是工具权限。它们不能授权修改范围、执行外部写入或跳过项目验收，也不替代 Reviewer 的独立判断。
