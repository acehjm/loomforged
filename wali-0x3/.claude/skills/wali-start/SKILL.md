为以下需求建立 WALI 工作状态：

`$ARGUMENTS`

1. 读取 `CLAUDE.md`、现有四个状态文件、相关代码和仓库命令配置。
2. 如果已有 `active`、`waiting_user` 或 `blocked` 目标，不覆盖它；先说明新需求与现有目标的关系，必要时请用户决定是追加、替换还是后续排队。
3. 在 `goal.md` 写明目标、背景、范围、非目标、约束、带 ID 的验收条件、检查方式、停止条件和用户确认项；初始化 `waiting_for: none`、空 `waiting_detail` 和空 `blocked_reason`。
4. 验收条件必须可观察。区分 `automatic` 和 `human`，每项定义所需证据。
5. 先选择最简单可行的执行方式，再在 `todo.md` 创建可在单个会话内验证的任务，标明依赖、负责人、必要性、文件范围和任务验收条件。
6. 初始化或保留 `issues.md` 中仍有效的问题；不得为了新目标清空历史未关闭问题。
7. 更新 `progress.md`，记录基线分支、工作区、发现的项目命令、基线验证和第一项可执行任务。
8. 新目标保持 `draft`，供用户检查。输出目标摘要、执行方式及理由、首个增量、未知项，以及可直接使用的 `/goal` 条件草案。

不要在目标仍含有会实质改变实现方向的未知项时开始编码。
